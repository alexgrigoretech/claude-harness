# Save

Persist the session state so a fresh session, or another machine, can resume without re-explanation. One pass. Ask nothing; skip a step that has nothing worth persisting and say so.

1. Summarize what changed this session in three to eight bullets: what was built, fixed or decided, exact file paths and commands, any number that is now canonical, what is still open.
2. Find the active planning doc: the plan or handoff file loaded or created this session (`~/.claude/plans/*.md`, `HANDOFF-*.md` in the project, or the project's own convention such as `*_HANDOFF.md`, `PIPELINES.md` and `ARCHITECTURE.md` when the project CLAUDE.md names them). If none exists, create `~/.claude/plans/<project>-<topic>.md`. Update it with: done this session, in progress, next steps, open questions, exact paths and commands to resume. Operator-facing run commands go to the operator doc, data-flow changes to the architecture doc, a deliverable's state to its own handoff; never everything into one file.
3. Update auto-memory only for durable, non-obvious facts: decisions with their why, gotchas, constraints, corrected assumptions. Patch the existing topic file rather than creating a duplicate; convert relative dates to absolute; add or refresh the one-line pointer in `MEMORY.md`; keep every index line one sentence and warn when `MEMORY.md` passes 20 KB. Nothing that the repo, the docs or git history already record.
4. Canon: if the session verified or overturned a fact that the project CLAUDE.md, the user CLAUDE.md, a machine file or a memory marked as canon states (a figure, a status, a ruling, a tool that no longer works), patch that file in place in the same pass and date the change. A fact that lives only in the handoff is not canon, and the next session will contradict it.
5. Ledger, only where `tools/masterplan.py` exists in the install folder (say "no plan tools here" and skip otherwise): for every decision id of the harness plan register (section 9 of the harness plan) whose status changed this session, append one record with `python <install folder>/tools/masterplan.py record <id> <status> --evidence "<the check that proves it>" --session <session id>`, where status is one of partial, "not started", yours or parked; done is never recorded by hand, the masterplan table certifies it from the registry check at the next run. Skip the step when no decision moved and say so.
6. If the trigger was "handoff": also write `HANDOFF-YYYY-MM-DD-<topic>.md` in the project root with state, open items, next steps and the exact resume commands, and print a one-paragraph resume prompt the user can paste into a fresh session on any machine.
7. Clear-safety check, always: the user will `/clear` right after this and resume from the handoff alone. Re-read the handoff's resume section and confirm it names every decision taken this session, every background job still running (task id, what it writes, how to check), every input still owed by the user, and every file a fresh session must open. Anything in the session scratchpad that the resume depends on (briefs, Codex output files, eval outputs, diffs) is copied into the project (`.scratch/` or the handoff's folder) and referenced by that path, because the scratchpad is session-specific. If anything is missing, write it, then end with "safe to /clear" and the resume command; if something cannot be persisted, say what and why instead.
8. Reply with the paths edited (one line each with why) and a three-line summary of what was saved. No em dashes.
