# Delegate

The Codex-first rule: Claude plans, orchestrates and verifies; Codex implements. This skill is the delegation step.

Implementer: read `codex_first` from `~/.claude/local/machine.json`; true (the default when absent) means the Codex branch below; false means the Claude branch after the Codex steps. Both branches use the brief template in step 2, the verification in step 6 and the report format in step 8. Use the implementer name in place of `codex` in scratchpad file names: `<scratch>/claude-<topic>-out.md` for the Claude report; `claude-<topic>-run.log` is not needed since the Agent result is the log.

1. Decision gate: say "Delegating to Codex" or "Delegating to a Sonnet agent", according to the branch, before the first code edit of the task.
2. Brief: copy `~/.claude/templates/codex-implementation-brief.md` into the session scratchpad as `brief-<topic>.md` and fill every section: files it may touch, exact behavior, constraints, acceptance criteria with the commands that prove them, and what done means. Paste measured numbers; never let Codex guess a value, a column name or a path. No client data, real identifiers or credentials in a brief. Bake verified version facts in; Codex has no docs lookup.
3. Model: read `codex_model` from `~/.claude/local/machine.json` (gpt-6.1-sol where the login has it, as the machine json says) and pass it explicitly. The wrapper in step 4 passes it and exits 1 when the exec header names another model; with the raw command, confirm the header's model line yourself.
4. Run, from the Bash tool, through the wrapper in the harness install folder (named in `~/.claude/local/machine.md`), with the brief and every output in the scratchpad:
   `python <install folder>/tools/codex_run.py exec --repo <repo> --prompt <scratch>/brief-<topic>.md --out <scratch>/codex-<topic>-out.md --log <scratch>/codex-<topic>-run.log`. It reads `codex_model` and `codex_effort` from `~/.claude/local/machine.json` (effort high by default, no override when null; `--model` and `--effort` override them) and runs `codex exec - -C <repo> -m <model> -c model_reasoning_effort="<codex_effort>" --sandbox workspace-write --output-last-message <out>` with the brief on stdin and the log capturing everything. Use that raw command only where the tool is missing. Non-git folders need `--skip-git-repo-check`. Long runs go to the background with a long timeout; never pipe a long run through `tail`, it buffers.
5. Read the wrapper's exit code before the summary: 0 the report was written, 1 Codex failed or ran on a model other than the one asked (the log says which), 2 quota, which includes the old trap of exit 0 with no output file, 3 bad arguments. Its first line names the session, model and provider, and its last line starts with `next:` and gives the one next command. On 2, the quota resets at a fixed local time on some logins and is a rolling window on others; the machine file says which. Schedule a wakeup for the printed reset (ScheduleWakeup or a note in the handoff) and run the resume command from the `next:` line when it fires. With the raw command, the same rule is checked by hand: the output file must exist before exit 0 means anything.
   Codex out: when the run or resume ended in a quota event (the wrapper exited 2; with the raw command, a usage-limit line in the log or exit 0 with no output file) and the printed reset is later than the end of the working day, or every login in the pool is at its limit, do not wait. Say "Codex out until <reset>, delegating to a Sonnet agent" and run the Claude branch below for the rest of the task. The guard hook still applies to the agent's edits: the first time the agent reports a block, write the exception line "Codex unavailable until <reset>, Claude branch for <task>" into `~/.claude/direct-edit-ok` (the named exception of the global CLAUDE.md, Codex failed or unavailable, written after the failure and never before it) and rewrite the same line on the next block after it expires. Every edit under the marker is logged with that line, including any the orchestrator makes itself, so the log shows the task and the reason. Record the Codex session id in the handoff so the next day's follow-ups resume it instead of starting fresh.
6. Read CHANGED FILES, VERIFIED and ASSUMPTIONS/RISKS. Each is a claim. Run the verify-pass skill or at least: `git diff --stat` against the allowed file list, re-run every VERIFIED command, and exercise the change. Codex has previously claimed edits that never landed, overwritten a file mid-flight, implemented a plausible neighbour of the spec, and reported tests it did not write.
7. Resume step, used by the auto, ship, verify-pass and pr-review skills: Codex branch below, Claude branch in the sub-list. Write the finding and the exact fix wanted to `<scratch>/finding-<N>.md`, then send it through `python <install folder>/tools/codex_run.py resume <id> --prompt <scratch>/finding-<N>.md --out <scratch>/codex-<topic>-out.md --log <scratch>/codex-<topic>-resume<N>.log` (it runs `codex exec resume <id> -m <model> -c model_reasoning_effort="<codex_effort>" -c sandbox_mode="workspace-write" -` with the finding on stdin and reads the exit the same way as step 5), numbering the resumes from 1 so the log names stay in order (the daily collector reads them where the plan tools are installed), never through a fresh run and never by editing the code yourself. After the second resume that does not land the fix, resume once more with `--model gpt-6-astra` where the login has it (the machine file says); otherwise stop after the second failed resume and hand the residue to the user.
8. Report: what Codex changed, which verification ran, the result, the model used.

Claude branch:

1. Run: use the Agent tool with `subagent_type` general-purpose, `model` sonnet, `effort` high, the brief file content as the prompt plus the sentence "Your final message must use the exact CHANGED FILES, VERIFIED, ASSUMPTIONS/RISKS format from the brief". Run it in the background when the acceptance commands take more than a minute. Write the agent's final report to `<scratch>/claude-<topic>-out.md` yourself before reading it, so step 6 reads the same file shape in both branches. Report what the agent changed in place of what Codex changed in step 8.
2. Quota: a usage-limit error from the agent is the equivalent of the Codex empty output file; record the agent id in the handoff and resume it with SendMessage when the window resets.
3. Resume: write the finding and the exact fix wanted to `<scratch>/finding-<N>.md` as in step 7 and send its content to the same agent with SendMessage (never a fresh Agent call, so the agent keeps its context), numbering the findings from 1. After the second resume that does not land the fix, start one fresh agent on `model` opus at `effort` high with the brief plus the finding history as the escalation; if that agent is unavailable, stop after the second failed resume and hand the residue to the user. Write the agent's final report to `<scratch>/claude-<topic>-out.md` before reading it and verify again through step 6.
4. Verifier: the verify-pass skill's separate mind is a general-purpose agent on `model` opus at `effort` high with the verification brief, in a detached worktree at the ref under review, never the agent that wrote the code.
5. Never edit the code yourself in either branch; the trivial-edit exception from CLAUDE.md still applies and is named when used.

Known Codex quirks: `--output-last-message` needs its directory to exist; sandbox temp dirs differ from the session scratchpad; orphan lock files after a killed run; PYTHONPATH is not inherited inside worktrees; background jobs get killed on low memory on some machines (run gates in the foreground where the machine file says so).

## Not done when

A state on this list looks finished and is not. Report it as the state it is, never as done; the status skill reads this list too.

- Both branches: CHANGED FILES names a file that `git diff --stat` does not show, or the diff touches a file the brief did not allow.
- Both branches: VERIFIED pastes a count that the orchestrator has not reproduced with the machine's own interpreter. A pass inside the implementer's own environment only is a claim.
- Codex branch: the run exited 0 and the output file is missing or empty. That is a quota stop (the Codex branch's step 5), whatever the exit code says.
- Codex branch: the exec header names a model other than the one passed. The banner alone does not prove the model.
- Claude branch: the agent's final message lacks the CHANGED FILES, VERIFIED and ASSUMPTIONS/RISKS blocks, or ended in a usage-limit error (the Claude branch's step 2).
