# Delegate

The Codex-first rule: Claude plans, orchestrates and verifies; Codex implements. This skill is the delegation step.

Implementer: read `codex_first` from `~/.claude/local/machine.json`; true (the default when absent) means the Codex branch below; false means the Claude branch after the Codex steps. Both branches use the brief template in step 2, the verification in step 6 and the report format in step 8. Use the implementer name in place of `codex` in scratchpad file names: `<scratch>/claude-<topic>-out.md` for the Claude report; `claude-<topic>-run.log` is not needed since the Agent result is the log.

1. Decision gate: say "Delegating to Codex" or "Delegating to a Sonnet agent", according to the branch, before the first code edit of the task.
2. Brief: copy `~/.claude/templates/codex-implementation-brief.md` into the session scratchpad as `brief-<topic>.md` and fill every section: files it may touch, exact behavior, constraints, acceptance criteria with the commands that prove them, and what done means. Paste measured numbers; never let Codex guess a value, a column name or a path. No client data, real identifiers or credentials in a brief. Bake verified version facts in; Codex has no docs lookup.
3. Model: read `codex_model` from `~/.claude/local/machine.json` (gpt-6.1-sol where the login has it, as the machine json says) and pass it explicitly. Confirm the banner prints it.
4. Run, from the Bash tool, with the brief on stdin and the output file in the scratchpad:
   `codex exec - -C <repo> -m <model> -c model_reasoning_effort="<codex_effort>" --sandbox workspace-write --output-last-message <scratch>/codex-<topic>-out.md < <scratch>/brief-<topic>.md > <scratch>/codex-<topic>-run.log 2>&1`. Read `codex_effort` from `~/.claude/local/machine.json`, high by default; when it is null, omit the `-c model_reasoning_effort` override in both commands.
   Inline prompts close stdin (`< /dev/null`) because Codex appends piped stdin. Non-git folders need `--skip-git-repo-check`. Long runs go to the background with a long timeout; never pipe a long run through `tail`, it buffers.
5. Before reading the summary: the output file must exist. Exit 0 with no output file means the Codex quota ran out mid-run. The quota resets at a fixed local time on some logins and is a rolling window on others; the machine file says which. Record the session id from the banner, schedule a wakeup for the reset (ScheduleWakeup or a note in the handoff), and resume with `codex exec resume <id>` when it fires.
6. Read CHANGED FILES, VERIFIED and ASSUMPTIONS/RISKS. Each is a claim. Run the verify-pass skill or at least: `git diff --stat` against the allowed file list, re-run every VERIFIED command, and exercise the change. Codex has previously claimed edits that never landed, overwritten a file mid-flight, implemented a plausible neighbour of the spec, and reported tests it did not write.
7. Resume step, used by the auto, ship, verify-pass and pr-review skills: Codex branch below, Claude branch in the sub-list. Write the finding and the exact fix wanted to `<scratch>/finding-<N>.md`, then send it on stdin through `codex exec resume <id> -m <model> -c model_reasoning_effort="<codex_effort>" -c sandbox_mode="workspace-write" - < <scratch>/finding-<N>.md > <scratch>/codex-<topic>-resume<N>.log 2>&1`, following step 4's null rule and numbering the resumes from 1 so the log names stay in order (the daily collector reads them where the plan tools are installed), never through a fresh run and never by editing the code yourself. After the second resume that does not land the fix, resume once more with `-m gpt-6-astra` where the login has it (the machine file says); otherwise stop after the second failed resume and hand the residue to the user.
8. Report: what Codex changed, which verification ran, the result, the model used.

Claude branch:

1. Run: use the Agent tool with `subagent_type` general-purpose, `model` sonnet, `effort` high, the brief file content as the prompt plus the sentence "Your final message must use the exact CHANGED FILES, VERIFIED, ASSUMPTIONS/RISKS format from the brief". Run it in the background when the acceptance commands take more than a minute. Write the agent's final report to `<scratch>/claude-<topic>-out.md` yourself before reading it, so step 6 reads the same file shape in both branches. Report what the agent changed in place of what Codex changed in step 8.
2. Quota: a usage-limit error from the agent is the equivalent of the Codex empty output file; record the agent id in the handoff and resume it with SendMessage when the window resets.
3. Resume: write the finding and the exact fix wanted to `<scratch>/finding-<N>.md` as in step 7 and send its content to the same agent with SendMessage (never a fresh Agent call, so the agent keeps its context), numbering the findings from 1. After the second resume that does not land the fix, start one fresh agent on `model` opus at `effort` high with the brief plus the finding history as the escalation; if that agent is unavailable, stop after the second failed resume and hand the residue to the user. Write the agent's final report to `<scratch>/claude-<topic>-out.md` before reading it and verify again through step 6.
4. Verifier: the verify-pass skill's separate mind is a general-purpose agent on `model` opus at `effort` high with the verification brief, in a detached worktree at the ref under review, never the agent that wrote the code.
5. Never edit the code yourself in either branch; the trivial-edit exception from CLAUDE.md still applies and is named when used.

Known Codex quirks: `--output-last-message` needs its directory to exist; sandbox temp dirs differ from the session scratchpad; orphan lock files after a killed run; PYTHONPATH is not inherited inside worktrees; background jobs get killed on low memory on some machines (run gates in the foreground where the machine file says so).
